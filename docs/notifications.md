# 자동 기기 알림 등록 — 1.0.124

## 배포 전 필수 설정

`js/push-config.js`의 `vapidPublicKey`에 Firebase 프로젝트 `rmpj-7ca13`의 공통 VAPID 공개 키를 설정했다. 키는 65바이트 비압축 공개 키 형식으로 검증했다. 비공개 VAPID 키나 서비스 계정 JSON을 클라이언트에 넣지 않는다.

## 사용자 동작

- 설정에는 `알림 — 허용됨 / 미허용` 박스만 남긴다. 테스트 화면, 공개 키 입력, 기기 토큰 표시·복사를 제거한다.
- 미허용 상태의 클릭에서 OS 권한을 직접 요청한다. 거부한 권한은 OS 설정에서 변경해야 한다.
- 권한이 허용된 로그인 사용자는 기기의 FCM 토큰을 자동 발급·확인하고 본인 계정에 등록한다. 이미 허용된 기기는 앱 재실행·복귀·온라인 복구 때 자동 확인한다.
- 게스트에게는 권한만 요청하며 로그인 후 기기를 연결한다. iOS는 홈 화면 설치 및 16.4 이상이 필요하다.
- 앱은 기기 등록을 처리한다. 수동 발송은 `notification-server/README.md`의 GitHub Actions 경로로 별도 준비되어 있으며 Firebase 인증·색인 최초 연결이 필요하다. 운동 기록 조회, 명언 예약 발송은 포함하지 않는다.

## 저장 구조와 사용량

`users/{uid}/pushDevices/{deviceId}`에 `{token, enabled: true, platform, updatedAt}`을 저장한다. 기기 ID는 설치 환경의 로컬 무작위 ID이며 계정별 하위 경로를 사용하므로 다른 사용자의 기록을 덮어쓰지 않는다. 로컬에는 계정/기기 연결 및 토큰 SHA-256 지문만 보관하고 원문 FCM 토큰은 Firebase SDK의 자체 저장 외에 복제하지 않는다.

- 등록을 위한 Firestore 조회는 하지 않는다.
- 첫 등록·토큰 변경 때 1회 문서 쓰기. 같은 토큰은 성공 확인 후 7일간 재쓰기하지 않는다.
- 토큰이 같아도 7일이 지나면 갱신 시각을 1회 반영한다. FCM SDK의 자체 등록/갱신 통신은 Firestore 조회와 별개다.
- 정기적 타이머 조회는 없다. 앱 복귀 등에서 확인한다.
- 허용 표시 자체는 OS 권한이다. 서버 연결 실패 시 허용 표시를 거짓으로 바꾸지 않고 안내 문구를 표시한다.

## 계정과 해제

로그아웃 전에 등록 작업을 직렬화하여 새 문서가 늦게 재생성되지 않도록 막고 브라우저 푸시 구독과 해당 계정의 기기 문서를 정리한다. 명시적 로그아웃이 아닌 계정 전환에서는 이전 계정 토큰을 재사용하지 않도록 구독을 회전시킨다. 새로운 계정 자격으로 이전 계정 문서를 삭제하지 않는다.

연결 정리가 오프라인 등으로 실패하면 회전 필요 상태를 로컬에 남겨 다음 계정 등록 전 다시 정리한다. 이전 계정에 남은 무효 토큰 문서는 향후 발송 서버가 FCM `UNREGISTERED` 응답을 받으면 제거해야 한다. 서버 발송 기능을 구현할 때 포함할 사항이다.

서비스워커는 로그인·등록 완료 계정을 로컬 캐시에 기록한다. 로그아웃 상태나 다른 계정의 `data.receiverUid`에 해당하는 푸시는 내용 대신 일반 안내만 표시하여 계정별 내용 노출을 방지한다. 웹 푸시의 가시적 알림 요건 때문에 수신 이벤트를 단순히 무시하지 않는다. 수동 발송 서버는 `data.receiverUid`를 반드시 포함한다.

회원탈퇴 데이터 열거에 `pushDevices`를 포함하며, 탈퇴 재인증 성공 후 기기 연결을 정리하고 기존 삭제 절차를 따른다. SDK/네트워크 작업은 대기 시간을 제한한다. 데이터 삭제 및 계정 변경 중 새 기기 문서 저장은 막는다.

현재 사용자 제공 규칙의 `/users/{userId}/{document=**}` 소유자 전용 접근이 이 경로를 허용한다. 규칙을 별도로 좁히는 경우에도 본인 `pushDevices`에 대한 create/update/delete만 허용해야 한다. 다른 계정의 토큰을 읽게 열어두면 안 된다.

## 검증

- `node --test tests/push-devices.test.cjs tests/push-worker.test.cjs tests/core.test.cjs`
- `python tests/notification-settings-smoke.py`
- `python tests/settings-glass-smoke.py`
- `python tests/browser_smoke.py` (로컬 서버 8000 필요)

자동 테스트는 격리된 Firebase와 알림 API를 사용한다. 기존 iOS 수신은 사용자 제공 API 200 응답과 알림 배너로 확인되었다. 공통 키를 넣은 자동 등록 배포 후 iOS/갤럭시의 새 기기 문서 생성 및 실제 푸시 수신은 다시 확인해야 한다.

## 기기 수신 진단

허용된 설정 알림 행을 누르면 서비스 워커 버전, 기기 구독 유무, 로컬 계정 등록 확인, 최근 푸시 수신 시각과 표시 요청 결과를 보여준다. 진단은 기기 캐시에만 마지막 1건을 저장하며 메시지 내용·토큰·계정 ID를 저장하지 않는다. 캐시 버전 변경 시 초기화된다. `shown`은 브라우저의 표시 API 완료이며 실제 배너 노출 보장은 아니다. 수신 기록이 없다는 결과만으로 서버·네트워크·기기 중 원인을 단정하지 않는다.

## 임시 제공 범위

현재 알림은 iOS 홈 화면 앱에서만 제공한다. 안드로이드 및 데스크톱은 준비 중으로 표시하고 권한 요청·FCM 토큰 발급·신규 등록을 하지 않는다. 기존 로컬 등록이 있으면 온라인 복귀 시 구독과 현재 계정의 기기 문서를 정리한다. OS의 기존 알림 권한을 프로그램에서 변경하지 않는다. 앱을 다시 열지 않은 기기의 서버 문서는 아직 남을 수 있으므로 수동 발송 서버도 `platform === ios` 및 `enabled === true`인 대상만 선택한다. 운동 기록 등 다른 기능은 변경하지 않는다.
