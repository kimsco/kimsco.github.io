# iOS 알림 수신 테스트 — 1.0.117

현재 범위는 수동 알림 테스트뿐이다. 자동 운동 리마인더, 예약 서버, Firestore 토큰 저장 및 운동 기록 조회는 추가하지 않는다. 결제 요금제 변경도 필요 없다.

## 아이폰에서 먼저 확인

1. iOS 16.4 이상의 Safari에서 앱을 홈 화면에 추가한다.
2. 홈 화면 아이콘으로 앱을 열고 설정 → 알림 테스트 → 알림 허용을 누른다.
3. 기기 테스트 알림을 누른다. 서비스워커의 `showNotification`으로 OS 알림 표시만 확인하는 로컬 테스트다. 원격 푸시 수신을 증명하지는 않는다.

## 실제 원격 푸시

1. Firebase 프로젝트 설정 → Cloud Messaging → 웹 푸시 인증서 → 키 쌍 생성. 공개 VAPID 키만 필요하며 비공개 키·서비스 계정 JSON을 앱이나 저장소에 넣지 않는다.
2. 앱의 원격 푸시 테스트 준비를 펼치고 공개 키를 입력한 뒤 이 기기 푸시 등록을 누른다. 기존 `/sw.js` 등록을 그대로 사용한다.
3. 토큰 복사 후 Firebase 콘솔의 메시지 작성/알림 화면에서 테스트 메시지 전송을 열어 FCM 등록 토큰에 붙여넣는다. 콘솔의 메뉴 이름은 버전에 따라 다를 수 있다.
4. 제목 `TTT 테스트`, 본문 `푸시 수신 확인`을 입력한다. 앱을 닫거나 아이폰을 잠근 뒤 테스트 메시지를 전송한다.
5. 수신과 알림 탭 후 앱 복귀를 실제 아이폰에서 확인한다. 집중 모드·알림 요약 설정에 따라 표시가 지연될 수 있다.

공개 키는 기기 로컬에만 저장한다. FCM 토큰은 현재 테스트 화면 메모리에만 유지하며 Firestore·별도 서버·로그에 기록하지 않는다. Firebase 설치/기기 등록을 위한 FCM 요청은 발생한다. 토큰은 재설치·등록 갱신으로 달라질 수 있으므로 테스트할 때 현재 토큰을 사용한다.

권한 차단은 iOS의 앱 알림 설정에서 변경한다. 기존 기기에서 권한을 허용했더라도 다른 홈 화면 설치나 브라우저에는 별도로 허용이 필요할 수 있다.

## 구현 및 검증

- `js/push-test.js`: 권한은 사용자 클릭에서 직접 요청한다. Firebase Messaging SDK는 푸시 등록 버튼을 누를 때만 동적으로 불러온다.
- `sw.js`: Web Push 수신 시 OS 알림을 표시한다. 알림 링크는 앱과 같은 출처만 허용한다. 기존 열린 앱을 우선 포커스한다.
- `node --test tests/push-worker.test.cjs`
- `python tests/push-test-smoke.py`

자동 테스트는 가짜 알림 API와 Firebase를 사용한다. 실제 iOS 알림 권한 창, APNs/FCM 전달 및 잠금 화면 수신은 공개 VAPID 키 설정 후 실기기로 확인해야 한다. 이 문서는 실기기 수신 성공을 주장하지 않는다.

## 1.0.118 — 원격 알림 미수신 확인

‘기기 테스트 알림’ 성공은 OS 표시 권한만 증명하며 원격 수신 연결을 보장하지 않는다. ‘연결 상태 확인’은 활성 서비스워커와 메시지 채널로 통신하고, PushManager 구독 존재 및 입력한 VAPID 키 일치를 확인한다. 이전 서비스워커가 실행 중이면 업데이트 안내를 표시한다. 등록도 수신 코드 응답을 확인한 뒤 진행한다.

실제 push 이벤트가 도착하면 수신 시각과 `showNotification` 결과만 현재 앱 캐시에 보관한다. 제목·본문·기기 토큰·푸시 구독 endpoint는 저장하지 않는다. 따라서 미도착과 도착 후 표시 실패를 구분할 수 있다. 앱 버전 업데이트로 해당 기록은 지워질 수 있다. `displayed=true`는 OS 표시 요청이 정상 완료되었다는 뜻이며 사용자가 알림을 실제로 봤다는 뜻은 아니다.

‘푸시 연결 다시 만들기’는 사용자가 누를 때만 현재 등록 토큰을 해제하고 같은 서비스워커와 공개 키로 새 구독·토큰을 생성한다. 이전 토큰은 사용할 수 없으므로 새 토큰을 Firebase 콘솔에 다시 붙여넣어 테스트해야 한다. 운동 기록·로그인·기존 앱 캐시 전체는 삭제하지 않는다. VAPID 키 변경 시 Firebase SDK가 기존 PushSubscription을 그대로 재사용할 수 있어, 키 불일치는 자동으로 덮어쓰지 않고 명시적으로 안내한다.

프로젝트 ID `rmpj-7ca13`와 공개 키 발급 프로젝트, 테스트 발송 프로젝트가 일치해야 한다. 테스트 전송 UI에서 오류가 없다는 사실만으로 기기 도착을 확인할 수는 없다. 이번 변경은 원인을 확인하고 구독을 복구할 수 있게 하며, 실제 iOS 원격 수신 성공은 여전히 실기기로 검증해야 한다.
